It's been about a month since I announced the free version of SaaS Pegasus, and the reception has been great so far! I love finally having something I can share and work on with a broader community. The most exciting thing to happen in the last month was BugBytes (one of my favorite coding YouTubers) making a very positive video about it.

In my last email I said my goal was to make Pegasus the best way to start a Django project. I've been thinking a lot about that goal and what it means as the coding landscape rapidly changes out from under us. To me, it means having a codebase that lets people and agents seamlessly collaborate.

The human part is something I've always strived for: keeping the code minimal and clean, having great docs, and adopting better tools and technologies as they gain critical mass. Fortunately, these things are also great for agents. But agents have their own unique requirements.

One of the things I've been reading and thinking a lot about lately is verification. In the context of agents, that means: how does the agent know that it did its task correctly? How does it know the new code works? And, maybe more importantly, how does it know it didn't break anything else? The more tools you give an agent to verify its work, the safer you can feel handing the agent larger tasks and not reviewing every change line-by-line.

To that end, this month I leaned into improving automated verification in the Pegasus foundation. This included significantly expanding the test suite, adding stronger type verification, and expanding the linting rules. Below are some quick details on these changes.

Expanding the test suite

I worked with Claude Fable to find places in the generated codebase that had limited test coverage, and then carefully reviewed and curated a test suite targeting those places. The result is that projects now ship with a lot more tests! This of course means that you and agents can more safely make changes in the surrounding code and be notified if something trips. Writing these tests even turned up a handful of real—if obscure—bugs, which I also fixed.

Stronger typing

Just like tests, types are a great way to catch latent bugs in your code. Charlie Marsh (founder of Astral, the company that makes ruff and uv) highlights these three benefits:
Improved readability: with type annotations, code tends towards self-documenting (and the accuracy of that documentation can be statically enforced, unlike in a docstring).
Catching bugs: it's true! Mypy does catch bugs. All the time.
Refactoring with confidence: With extensive Mypy coverage, I can confidently ship changes that span hundreds or even thousands of files.
Of course, all of these things are great for agents! Especially the refactoring bit.

In keeping with that, Pegasus has much stronger typing now, and this is something I'll continue to lean into. Just like the tests, adding types did in fact also catch a few latent bugs, which of course I fixed.

Stricter linting

Speaking of ruff, the latest release drastically expanded the default rule set. I went ahead and enabled this on Pegasus, and it was able to clean up a lot of small violations and, again, catch a bug or two.

All of these changes continue to work towards the same goal: make Pegasus the best Django foundation for humans and agents alike. For the complete changes—including package upgrades, expanded translations, and more—check out the full changelog or complete diff from the last release.
